# 项目结构与命名约定

## 目录职责

| 目录 | 用途 |
| --- | --- |
| `app/` | 产品页面、页面元信息与全局样式 |
| `public/images/archive/` | 全家福、旧照片和档案类素材 |
| `public/images/brand/` | 社交分享图等品牌素材 |
| `public/images/portraits/` | 人物肖像素材 |
| `worker/` | 线上运行入口 |
| `build/` | Sites 与 Vite 构建适配代码 |
| `db/` | 后续持久化功能的数据访问层 |
| `drizzle/` | 数据库迁移元数据 |
| `tests/` | 页面构建和渲染测试 |

## 命名规则

- 文件和目录统一使用小写 `kebab-case`。
- React 组件使用 `PascalCase`。
- TypeScript 变量和函数使用 `camelCase`。
- 静态素材使用“内容—用途”式英文名称，不使用 `person-01` 等无语义编号。
- 人物专属图片用人物拼音，如 `chen-deshan.jpg`。
- 通用档案图片按内容命名，如 `chen-family-1956.jpg`。

## 当前阶段边界

当前是前端体验 Demo：人物数据写在页面代码中，创建档案不会持久化。进入正式开发阶段后，建议依次拆分为：

1. `data/`：演示人物与家族资料；
2. `components/`：人物卡、详情、族谱、二维码等界面组件；
3. `lib/`：搜索、语音、二维码与数据导出逻辑；
4. `db/`：用户、人物、媒体、亲属关系和修改历史。

在引入真实用户数据之前，必须先确定实名认证、内容授权、隐私分级和资料导出规则。
